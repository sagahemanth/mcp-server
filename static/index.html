Airline Care training demo

All passenger, booking, policy, payment, loyalty, and case-management records are simulated. Actions do not affect real airline systems.

Workflow: classify the request → collect a booking reference → verify the passenger’s last name → retrieve context → check the versioned policy → present an option → wait for explicit confirmation → submit and report the returned transaction status.

Sample booking surnames: PNR482 — Rivera · PNR739 — Morgan · PNR615 — Patel · PNR901 — Kim. If you generate a random ticket, the app uses the last name in your browser-only demo profile.

The profile is not secure authentication and is not connected to Firebase. When configured, the model shown on screen assists intent, context, policy explanation, resolution preparation, and escalation. Identity and action safeguards remain deterministic. Never enter real passenger data.
